## What the data actually says

- **Run-to-run variance dominates.** Identical upstream baseline runs on the same task ranged 340–472 s
  (39%) and 353–458 s. At one repetition per task a screen cannot detect effects smaller than roughly 30%.
  None of the three ratios above is a statistical claim (2 task clusters; no CI).
- **HC03's apparent gain is noise.** Its own receipts show `requested_effort=None` on every request: the
  loop delivers tool results as user-role messages with `tool_result` blocks, so the phase classifier
  treated each request as the first of a turn. Root cause identified; fix pending (HC03b).
- **Instrumentation is the durable result.** `fast_decisions:source` (provenance), observation stats on
  `requested`, `effort_routed` receipts, side-sourced receipt extraction, mode receipts, and a resumable
  budget-enforced runner (`scripts/campaign.py`) that reserves before every paid launch, never treats a
  Forge observation timeout as completion, and retries an infrastructure failure at most once.
- **Cheap smokes paid for themselves.** Two haiku pairs ($0.72) caught the candidate silently running in
  shadow mode and receipts being filtered by the installed package's allowlist before any $3 run was spent.
