# Orchestrator-primary fast-decisions: results (2026-09-24)

Branch `feat/orchestrator-primary`. The design is in [ORCHESTRATOR-PRIMARY.md](ORCHESTRATOR-PRIMARY.md),
the protocol in `evals/STUDY-DESIGN.md` §18. Unless marked "3 reps", every number here is a
**screen** (fewer than 3 reps, or dev split only), not a confirmed finding.

## The shape we landed on

1. **Orchestrator-primary composition.** `bundle.md` / `behaviors/fast-decisions.yaml` replace the
   host's `loop-streaming` with `loop-fast-decisions`, which wraps it. Upstream steering, approvals,
   compaction, cancellation and the provider pin keep working. The root's loop config is forwarded.
   Sub-sessions inherit the orchestrator. The dashboard launches from the orchestrator.
2. **One routing decision per turn.** A typed simple/complex question, asked before the first provider
   call, picks model **and** effort for the whole turn, so the prompt cache is never re-written
   mid-turn.
3. **Quality-safe scope gate.** Repository-scale workspaces (more than 300 files) always start on the
   host model. Cheap-first lost quality there.
4. **Pluggable judge.** No judge (length rule) by default. Jev, or a local model, via the
   `overrides.loop-fast-decisions.config` settings override. Local models answer Jev-style typed
   questions.

## Simple tasks (S1 battery, 12 dev tasks)

Time and cost are geometric means of per-task ratios against plain in the same batch (STUDY-DESIGN §8).

| Config | Time vs plain | Cost vs plain | Quality |
|---|---|---|---|
| plain-sonnet (model-swap control) | 0.59x | 0.42x | 12/12 |
| orch-primary v0 (cheap-first, phase effort) | 0.48x | 0.77x | 12/12 |
| **router, shipped default (length rule; pre-scope-gate build 43ed54e)** | **0.55x** | **0.38x** | 12/12 |
| router + Jev | 0.61x | 0.50x | 12/12 (Jev sent 3/12 strong) |
| effort routing alone, same model (fable) | 0.77x | 1.09x | 12/12 |
| **shipped default, preregistered holdout (8 unseen tasks, 3 reps)** | **0.61x [0.47–0.78]** | **0.40x** | 24/24; sign test 7/8, p = 0.07: **not confirmed** (5 of 6 criteria passed; one task marginally slower, median 8.79 s vs 8.73 s) |

The dev battery is a ceiling suite: every config passes every task, so it cannot show small quality
differences.

1.4x more expensive because each switch rebuilt the prompt cache.)

## Amplifier overhead (the part neither the model nor the judge touches)

- A trivial prompt on this machine's real config (24 app bundles) takes **59 s** and sends a
  **114k-token** prompt. With app bundles disabled: 13 s. The model call is ~2 s either way. See
  the local `BUNDLE-CLEANUP.md` proposal.
- **Foundation `hooks-deprecation` walks all of `~/.amplifier`** on every session start, sub-agent
  sessions included: 5.8 s here. The upstream patch in `docs/upstream-patches/` cuts it to 0.002 s
  (72 existing + 6 new tests passing on Python 3.11–3.13; independently reviewed).
- On SWE-bench, waiting on the provider is about 80–84% of the turn; most of the rest is tools.
  Each run also spends ~12 s on startup and exit.

## Bugs found and fixed along the way (eval infrastructure)

- Receipts were silently dropped: the shared events dir exceeded the 100k-record window. Fixed with
  per-run events dirs.
- The report pipeline crashed on series labels containing `=`, and read `evaluate`'s stdout summary
  instead of `comparison.json`.
- Mechanism gates misread a routing-only config as "backend refused".
- The SWE-bench DTU scaffold never substituted `${SWE_REPO_*}`. A new Forge runner uses official
  swebench 4.x grading and the instance image as the agent's environment.
- Forge `run_command` returns after ~60 s. Completion is now signalled by `result.json`.
- A stale `.git/index.lock` produced empty patches. Patches are now captured through a private index.
- `file://` module activation installs `amplifier_fast_decisions` editable into the shared tool env.
  Runs now pin `PYTHONPATH` to the frozen source.
- Local judges refused every typed question. They now answer choice and noul questions.
