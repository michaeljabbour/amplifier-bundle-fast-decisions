Paired, same model, same 20 tasks — **Amplifier+fast-decisions vs Amplifier plain: time ratio 0.68 (geometric mean),
15 wins / 5 losses, exact two-sided sign test p = 0.041, cost ratio 0.76, quality identical (20/20 each).**
This is the first statistically supported result of the campaign; it is one repetition per task.

Where Amplifier's time and money go (from native receipts, mean per run): ~14 s from process start to the first
model call (bundle composition and module validation); ~47–52k cache-write tokens per run (the composed system
prompt, ≈$0.60 at $12.5/MTok); provider spans 74 s (fast-decisions) vs 118 s (plain) over 8.9 vs 11.4 requests.
The decision loop is not the dominant term against Claude Code or Codex; startup and prompt size are.

Measurement corrections applied before these numbers: Claude Code under the Forge daemon needs `--safe-mode`
(`--bare` drops keychain auth); the Amplifier worker counted `unittest` exit 5 (no tests found) as a failed
workspace suite — seven `edit` runs were re-scored deterministically from their workspaces (`battery.py reevaluate`),
no run was repeated.

## Verdict against the target ("outperform Claude Code / Codex / OpenCode on cost, quality, speed")

Quality: parity (Amplifier variants 20/20; others 19–20/20). Speed and cost: **not achieved.** Even with all-phase
effort routing Amplifier is ~2–4× slower than Claude Code/Codex on these prompts and ~4× costlier than Claude Code,
for reasons outside the decision loop: ~14 s startup and a ~50k-token system prompt per run. Fast-decisions did
deliver a real, measured improvement over plain Amplifier (0.68 time, 0.76 cost, p = 0.041).
